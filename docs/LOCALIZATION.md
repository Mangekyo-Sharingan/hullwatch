# Localization

Hullwatch extracts its player-facing strings from source into a single CSV table that Godot's
CSV importer turns into `Translation` resources. The extraction step is an inventory pass: no
game code calls `tr()` yet.

## Extraction

From the repository root (`E:\Projekt\Misc\OperationSpacer`, PowerShell):

```
& ".\Engine\Godot_v4.7.2-stable_win64_console.exe" --headless --path game --import
& ".\Engine\Godot_v4.7.2-stable_win64_console.exe" --headless --path game --script res://tools/extract_strings.gd
& ".\Engine\Godot_v4.7.2-stable_win64_console.exe" --headless --path game --import
```

The tool writes `game/assets/locale/strings.csv` and prints `PASS: extract_strings (N strings)`.
It scans `res://src/ui/*.gd`, `res://src/interactables/*.gd` (recursively) for strings assigned to
`text` properties and strings returned from `get_interaction_prompt()`, plus `res://src/data/manual/*.tres`
and `res://src/data/logs/*.tres` for `title`, `body`, and `date_text` fields.

Output is deterministic: same sources produce a byte-identical CSV. Keys are
`<FILE_SLUG>_<SOURCE_INDEX>`, e.g. `UI_STATUS_PANEL_01` for the first extracted literal in
`src/ui/status_panel.gd`, where the index is the literal's 1-based position among that file's
matched literals. Rows are deduplicated by value (first file in sorted order wins).

## CSV format

```
keys,en
UI_STATUS_PANEL_01,Close panel
UI_STATUS_PANEL_02,Read panel
```

- The first row is the header. The first column is the key column; the remaining columns are
  locale codes.
- Newlines inside a value are written as the two characters `\n` so every entry stays on one line.
- Values containing commas or double quotes are CSV-quoted, with inner quotes doubled.

## Adding a language

1. Add a new column to `strings.csv` with the locale code as header, e.g. `keys,en,de`, and fill
   the rows (leave a cell empty to fall back to the key or to English, depending on project settings).
2. Re-run the `--import` command. Godot imports the CSV as a `Translation` resource and generates
   the locale variants from the column headers.
3. Register the generated resource (`assets/locale/strings.en.translation`) under **Project Settings > Internationalization > Translations** (already done in `project.godot`).
   The `.en.translation` file is generated by the import step, so run the extractor and `--import` after cloning or after changing strings.
4. Switch languages at runtime with `TranslationServer.set_locale("de")`; look strings up with
   `tr("UI_STATUS_PANEL_01")`.

Removing or adding rows changes the file, so keep translations in sync by re-running the extractor
and merging new keys. Never edit the `keys` column by hand: it is regenerated on every run.

## Known limitations

- **Format strings containing `%` are not extracted yet.** Anything using `%s`, `%d`, or `%` is
  skipped because the runtime formatting has to be resolved before translation. Affected strings
  include the status panel readout, the sleep summary (`SLEPT %s`), the loss overlay, the O2 candle
  prompt (`Light O2 candle (%d left)`), and the leg-complete overlay.
- **Procedural audio has no text.** Audio cues and the AudioDirector produce no translatable strings.
- **Prompts built dynamically are not captured.** `get_interaction_prompt()` implementations that
  return instance data (for example `Interactable.display_name`) carry their text on exported node
  properties in scenes, not in the scanned files.
- **Strings longer than 500 characters are skipped.** Three manual bodies (`page_power`,
  `page_life_support`, `page_operations`) currently exceed the limit and are left out.
- **Runtime-composed readouts are not captured.** Labels assembled by joining generated lines
  (status panel, log terminal, maintenance board) are built from numbers and ids at runtime.
- **No `tr()` call sites yet.** Extracted strings still appear literally in code; wiring them to
  `tr()` is a follow-up step.
