# Current-candidate human acceptance record

Use after an exact build containing the October 14 work is made and verified.
The October 13 published v8 playtests do not contain the foundations or v10
survey notebook. Do not
mark the form complete from scripted checks or agent screenshot inspection.

## Candidate and environment

Record tag/filename, source/tree identity, SHA256, save version, hardware, OS,
resolution, UI scale, input device, start/end times and tester experience.
Keep test saves separate from the operator's real watches.

## Manual-only success test — M3 / PLAYTEST

Give the tester only the in-game manual. Let them choose actions. Record whether
they survive three simulated days, what fails, how they diagnose it, and whether
they can explain the cause and consequences without external hints. Record
spontaneous comments on low-power nights before asking about tension. Afterwards
ask what they wanted to repair next and when the work began to feel repetitive.
Collect results across testers before assessing the spec's 70% tension target.

## Continuous route — MANUAL

Record an uninterrupted inspection → diagnosis → correct repair → chosen travel
leg → approach → suit/airlock/EVA → useful sample/equipment return → resource
transfer → save → exit/restart/load route. Observe clarity, reachable controls,
movement/tether comfort, refusal messages and retained equipment/resources.
Exercise the water/charge and empty-shell/refill/patch paths using the manual.
Compare survey/salvage/endurance equipment with actual resource budgets.
Use the carried scanner to record an unknown contact, consult SURVEY NOTEBOOK,
prepare and return a physical sample, then revisit its saved evidence. Record
whether the uncertainty, costs and archived observations change a real choice.

## Beta / native platform

Record rendered FPS/frame-time behavior on representative hardware, including
interior, pods, streamed contacts, EVA, UI and sustained simulation. CPU fixture
timing does not stand in for these measurements. Check readability and controls
at normal/max UI scales, audio cues and keyboard-only menu dismissal. On native
Windows exercise new/load/overwrite/corrupt saves across all three slots, settings,
updates and restart; record exact coverage. Actual Deck controls/suspend/restart
remain distinct from Linux desktop results.

## Findings and acceptance

For each issue record reproduction, candidate identity, save, observed behavior,
expected behavior, severity and evidence. Record operator art/propulsion acceptance
explicitly. Attach completed results to the roadmap gates; unresolved P1 bugs,
missing native hardware and unperformed routes stay open.
